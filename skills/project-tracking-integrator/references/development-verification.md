# 开发检查、文档与闭环修复

## 文档落点

先查项目规则、契约、事件字典和 Tracking Map，复用权威来源，不建重复字典。没有来源时创建 `docs/tracking/events.md`，采用以下最小表格，只添加本次事件：

| 事件/平台 | 业务触发与排除条件 | 字段类型、固定规则及来源 | 次数/去重 | 方法与调用位置 | 代码检查 | 浏览器 | 平台数据 |
|---|---|---|---|---|---|---|---|

另记录验收环境、日期和证据摘要。未运行写“尚未验证”；失败写原因；检查与数据结论分开。修改字段或触发条件时更新原记录，不追加互相冲突的定义。用户明确禁止文档变更时遵从并说明未同步。

## 源码证据与补查

脚本通过项目已有 TypeScript/Vue 解析器检查目标函数、真实调用及传输 payload。`--scope method` 仅检查方法，默认 `integration` 还检查调用。类型或方法名出现、注释、单纯 import、其他文件的字段不算实现证据。

脚本不是控制流证明器。动态参数、对象展开、公共上下文、间接 transport、自动导入或模板调用无法静态证明时，返回具体中文原因及位置。Agent 继续读相关声明、参数来源、Nuxt 配置/生成导入表和触发所有者，必要时运行针对性测试。记录补查证据，不把脚本未确认项悄悄改成通过，也不以缺少显式 import 判定 Nuxt 不可达。

补查结果可作为单独 source 报告传给汇总器，必须包含事件 id、平台、状态、`method: agent-review`、`evidence`（位置与理由），并说明原检查缺口如何解决。新报告使用当前代码版本；不能沿用修复前的证据。没有依据的人工通过无效。

每项问题保留 `code`、中文 `message`、`location`、`impact`、`attempted`、`nextStep`；机器字段保持英文以兼容。未知状态显示“未知结果，需补充说明”，不得展示裸状态码。

## 修复决策

| 失败 | 下一步 |
|---|---|
| 定位不唯一、DOM 变化 | 重新读取 DOM，确定稳定范围，不用位置兜底 |
| 未登录或登录失效 | 请用户在选定会话登录并回复，重新验证后恢复 |
| 业务本身失败 | 判断是否本次引入；已有问题给出证据，不能擅自扩大修复 |
| 字段、触发、重复不符合需求 | 在开发授权内修复，重审业务影响、更新文档、新窗口验收 |
| 查询失败或权限不足 | 报告查询原因及缺失条件，不推断代码错误 |
| 查询成功但无数据 | 检查环境、关联及延迟；按有限查询重试规则处理 |
| 截断或环境值无法解析 | 证据不足，缩小窗口或修正数据条件后独立验收 |

最多三轮代码修复；同一原因连续两轮无新证据或进展提前停止。使用 `scripts/workflow-policy.mjs` 的状态决策辅助记录轮次、登录恢复和下一步；它不执行 UI、不替代业务影响判断，也不自动获取授权。

## 业务影响

业务影响检查始终在文档完成和正式业务触发前完成。执行 [business-impact-review.md](business-impact-review.md)，有限不确定性先补查，重大影响未解除时暂停。最终中文报告说明已完成阶段、未完成原因和恢复路径。

## 完整报告的开发证据

完整闭环汇总默认要求开发证据，使用 `--development <development-report.json>`：

```json
{
  "businessImpact": { "status": "PASS", "risk": "low", "evidence": ["业务方法路径:行号；已审查条件、异常、返回值及测试结果"] },
  "documentation": { "status": "PASS", "path": "docs/tracking/events.md", "evidence": ["本次事件记录及实际验证状态已同步"] }
}
```

这些值必须来自实际检查，不能为了通过生成空泛声明。浏览器报告的触发窗口必须与每项入库证据的 `queryWindow` 相同；其他平台手工证据也要记录实际查询窗口，不能复用其他事件或上一轮窗口。仅兼容旧独立报告时显式使用 `--mode legacy`，其结果不能称为本次闭环通过。

汇总同一事件、平台和环境的多轮报告时，按旧到新传入，最后一份替换前一份；状态、事件名、问题详情和时间窗必须来自同一份选中证据。修复后须同时提供新一轮浏览器和入库报告。源码检查须关联实际 SDK 导入及目标平台；全局 SDK、工厂初始化、GTM 路由或复杂别名无法自动证明时，由 Agent 补查并记录依据，不能仅凭方法名通过。

报告级环境与事件级环境不得冲突；时间窗缺失或不一致只能追加关联问题，不能覆盖已有查询或数据失败。静态检查仅自动认可可证明原样透传事件和字段的简单传输封装；改写、分支或额外操作须补查最终发送参数和执行条件。Vue 模板检查需保留循环及插槽绑定作用域，避免把同名局部函数当作导入的埋点方法。

完整闭环不能使用 `scope: method` 的源码结果替代调用检查；请重新执行 integration 范围检查，或另行提交包含调用点依据的 Agent 补查报告。目标未确定或没有可检查目标时，源码命令返回非成功结果并说明原因。

runner 导出的浏览器汇总证据会在旅程与步骤校验通过后，为 SDK 不可观测的事件补充独立的 `pageStatus: PASS`，同时保留原 `status: NOT_AVAILABLE`。不要在原始浏览器报告中手动添加此字段；汇总器仅将它用于页面阶段，不能替代契约要求的 runtime 发送证据。
