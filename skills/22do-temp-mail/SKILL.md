# 22.do 临时邮箱

通过 22.do API 获取一个临时邮箱地址，查询该邮箱的收件列表，并按 `messageId` 读取邮件正文。只在用户授权的测试场景中使用。所有面向用户的说明使用简体中文。

## 凭证

优先使用进程环境变量 `TWENTYTWO_DO_TOKEN`（22.do 账户 token），通过 `POST /token` 换取短期 Bearer token。若未设置，则使用 `TWENTYTWO_DO_EMAIL` 与 `TWENTYTWO_DO_PASSWORD` 调用 `POST /auth`。不要把账户凭证或 Bearer token 写入文件、命令历史、Skill、报告或回答；不要在输出中回显它们。缺少凭证时，说明需要配置哪些变量，不要索取用户在聊天中粘贴密码。

Base URL：`https://22.do/api/v2`。除 `POST /token` 和 `POST /auth` 外，每个请求都需要 `Authorization: Bearer <Bearer>`。请求和响应均使用 JSON。完整接口细节见 [22.do API 文档](https://22.do/document)。

## 工作流程

1. 读取可用凭证并获取 Bearer token。认证失败时停止并说明 HTTP 状态和服务端的非敏感错误信息，不重试凭证。
2. 获取邮箱：默认调用 `POST /account`。用户明确要求 premium 或 private 邮箱时，分别使用 `GET /account/premium` 或 `GET /account/private`。这些接口返回分配给账户的邮箱地址；不要假设 API 支持任意自定义邮箱名。
3. 将新邮箱地址展示给用户。查询收件箱时调用 `POST /inbox`，JSON body 至少包含 `{ "email": "<email>" }`。若用户给出起始时间，用 Unix 秒级时间戳作为 `time`，避免返回更早的邮件。
4. 展示收件列表时包含时间、发件人、主题和 `messageId`。用户要看某封邮件时调用 `POST /inbox/message`，body 为 `{ "messageId": "<messageId>" }`，再展示邮件的 `body`；只有正文缺失且用户需要时才展示 `html`。
5. 若用户要求等待新邮件，可间隔数秒重复查询，并以用户给定的等待时长为上限；未给时长则最多等待 60 秒。每次查询前核对是否已出现新 `messageId`。到时仍未收到时如实说明。

## 失败处理与隐私

- `401`：Bearer token 无效或过期；可重新认证一次，仍失败则停止。
- `404`：邮箱或邮件不存在，核对邮箱地址及 `messageId` 后报告。
- `422`：请求参数无效；修正已知的参数问题，不猜测或反复试探。
- `429`：停止轮询并遵从服务端限流提示，至少等待一秒后才可重试。文档说明通用限额为每账户每秒 20 次请求。
- 网络错误或 `5xx`：最多重试一次，短暂等待后再试；失败则报告。
- 邮件正文可能含验证码、登录链接或个人信息。只向当前用户展示其请求查看的邮件内容；不要转发、持久化或把邮件内容写入日志。未经用户明确要求，不调用删除邮件接口。
- 仅把该服务用于获准的测试邮箱收件；不得将它用于非法活动或绕过无权操作的网站验证。若构建使用此 API 的应用，依 22.do 文档在应用中注明并链接 22.do。

## 交付

简要给出邮箱地址、匹配邮件的时间/发件人/主题，以及用户所请求的邮件正文。未收到邮件、接口失败或正文不可用时，清楚区分实际结果与推测，不声称成功。
